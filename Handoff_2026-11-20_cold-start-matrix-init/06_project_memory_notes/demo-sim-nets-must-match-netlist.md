`test_netlists/` (repo root) holds the 3 canned demo netlist fixtures:
`AV-880_MTX_12net.xlsx` (12 nets), `AV-880_MTX_24net.xlsx` (24 nets),
`AV-880_MTX_118net.xlsx` (118 nets, matches the full demo harness from
`buildNets()` in `gui_flutter/lib/design/model.dart`). Generated by
`test_netlists/generate_test_netlists.py`. Both MTX and HV netlists now load
only via "Browse the file system…" — the old canned-entry pickers (incl.
`.hnl` HV entries) were removed as fabricated-metadata props during the "GUI
Reality Check" audit (closed in commit e5ec55c). See [[gui-flutter-only]].

The simulator (`gui_flutter/lib/htproto/simulator.dart`) only models the
net count it's told at launch (`makeScenario(nets: ...)`); it has no idea how
many rows are in whatever `.xlsx` file gets loaded afterward. `--sim` alone
defaults to `--nets 12`. Loading a netlist with more nets than that makes
every net past the simulated count read NOT CONNECTED → CONT RUN FAILs.

**Why:** Hit exactly this on 2026-08-17 — a demo run loaded
`AV-880_MTX_118net.xlsx` against a plain `--sim` (nets=12 default) and
produced a real FAIL report, right before the file was needed to demo to a
client.

**How to apply:** Before a client demo, launch with `--nets` matching the
file about to be loaded, e.g.
`flutter run -d windows --dart-entrypoint-args --sim,--nets,118` for the
118-net file. `gui_flutter/test/demo_fixture_smoke_test.dart` pins all three
fixtures passing `CONT RUN verify` at their matching net count — run it after
any simulator/netlist-parsing change to confirm the demo path still passes.
Real hardware (`--serial`) doesn't need this — the instrument reports its own
netlist.
