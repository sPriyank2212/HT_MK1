ARCHITECTURE (key fact)
--------------------------------------------------------------------------------
Single-MCU design. The STM32G474 on the Control Card is the ONLY processor in
the instrument. The Matrix Card and HV Cards have NO MCU - they are I2C GPIO
expanders (MCP23017), analogue muxes (CD4067), reed relays (MHV05), DACs and
ADCs driven by this one firmware over I2C / SPI / GPIO. All test logic lives here.

    Core/Inc/drivers, Core/Src/drivers   - device drivers
    Core/Inc/cards,   Core/Src/cards     - per-card abstraction
    Core/Inc/test,    Core/Src/test      - continuity / kelvin / insulation
    Core/Inc/bsp,     Core/Src/bsp       - board bring-up (bindings)
    Core/Inc/app,     Core/Src/app       - logging + RTOS tasks

BUS / PERIPHERAL MAP  (CORRECTED 2026-07-14 vs schematics - old map was wrong)
--------------------------------------------------------------------------------
    I2C2  PC4(SCL)/PA8(SDA)   -> HV-card MCP23017 x8  (isolated, ADUM1250)
    I2C3  PC8(SCL)/PC9(SDA)   -> Matrix MCP23017 x2   (isolated, ADUM1205 U103)
    SPI1  PA5/6/7, CS PB0     -> Matrix AD7476 U33 (HI_COM) = RESISTANCE measure
    SPI2  PB13/14/15, CS PB2  -> DAC8775 + HV DAC8830 + HV AD7476 x2 (ISOLATED,
                                 shared bus, per-device CS)
    SPI3  PB3/4/5, CS PB1     -> Control AD7476 U4 (ADC_IN) = CONTINUITY measure
    GPIO  OPT0_CNTR = PC12 (mode switch; the Op-Doc's "PA15" was WRONG = buzzer)
          HV_Card_x.0 / x.1  = the two ADC chip-selects per HV board (see below)

    - DAC8830 (HV V_PGM) is on SPI, NOT I2C (Op-Doc said I2C - wrong).
    - There is NO HV-enable and NO discharge GPIO: CA05P-5 VIN is tied to
      +5V_ISO, HV output follows the DAC only. HV OFF = program DAC to 0.
      Discharge is passive through the ~10.05 Mohm sense divider.
    - Each HV board has TWO AD7476: RAIL (U301 = HV_Sense) and LEAK (U302 =
      HV_RET, across R3004 1k = insulation). HV-card ADCs run off +5V_ISO ->
      vref 5.0 V. Control/Matrix ADCs = 3.3 V.
    - HV_Sense = HV * R3003/(R3001+R3003) = HV * 0.00049 ~= 0.245 V @500 V, a
      1:2000 divider (R3001 10M : R3003 5k). NOTE (v1.3): the present HV_Card
      sheet 2 labels R3003 = 50k (1:200 -> 2.49 V, x10); HW owner is changing
      R3003 to 5k in the next schematic revision. Firmware uses the 0.245 V /
      0.00049 scaling; reading sits well inside the 5.0 V ADC ref.

1) MCP23017 driver  -  Core/{Inc,Src}/drivers/mcp23017.{h,c}
--------------------------------------------------------------------------------
   Bus-agnostic 16-bit I2C GPIO expander driver (2x Matrix, 8x per HV Card).
   Init (HAEN, latch low, all outputs), WriteReg/ReadReg(16), WritePins/ReadPins,
   WritePin via shadow latch. Blocking HAL, 100 ms timeout. Complete.

2) Matrix Card layer  -  Core/{Inc,Src}/cards/matrix_card.{h,c}
--------------------------------------------------------------------------------
   Routes any of 256 pins onto HI/LO bus: shared 4-bit select per bank
   (HI_S0..3 / LO_S0..3), one-hot enables (HI_EN1..16 U101=0x20, LO_EN1..16
   U102=0x21), break-before-make. MATRIX_EN_ACTIVE_LOW=1 (CD4067 E active-low).
   NEW 2026-07-14: on-card AD7476 (U33 on SPI1, reads HI_COM) added -
   MatrixCard_InitAdc / ReadRaw / ReadVolts. This is the RESISTANCE sense point.
   NOTE: S0..3 pulled down + LO_COM pull-down = 100R (page 3) - the 100R also acts
   as the current-source return and the continuity low leg. Channel address is
   defined at power-up; the mux ENABLE lines are not pulled and float until the
   MCP23017s init (low risk; EN pull-ups to be added next schematic rev).

   SPI read-only 12-bit SAR driver, reused four places: Control U4 (SPI3),

 PENDING  -  FIRMWARE
================================================================================
   [!] insulation return scheme (v1.3, per HW owner): the leakage loop is
       +500V -> R3002 1M -> HS relay[n] -> HS wire -> [insul] -> adjacent conductor
       -> its LS relay -> HV_RET -> R3004 1k -> GND. Per line: energise HS[n] and
       close ALL Low-Side relays EXCEPT net n's own return (from the connection
       map); the net is measured against every other conductor. insulation.c MUST
       drive this LS pattern - with no LS relay closed the ADC reads ~0 = false PASS.
   [~] resistance test (v1.3, LO_COM=100R): U33 reads HI_COM vs GND (2-wire), so
       reading = I * (2*mux_Ron + 100R LO_COM return + R_wire). The 100R return lets
       current flow (100k made 10 mA impossible). BUT compliance != calibration: if
       mux Ron is high (CD4067B ~500R -> ~1.1k offset) the node needs ~11 V @10 mA and
       clamps at 3.3 V - current collapses regardless of any cal. Need low-Ron mux
       (~15R) and/or lower current so I*(offset+R_wire) < ~3.3 V. Planned self-cal: a
       known reference wire per side (GPIO-driven CD4067) measured before each test to
       characterise & subtract the offset - cal path MUST use the SAME switches as the
       measure path, else the main-mux Ron is not cancelled. Floor after cal = ADC
       LSB/I (~80 mR @10 mA) -> ohms-range OK, not milliohm (that needs 4-wire). kelvin.c.
   [x] continuity level (v1.3): LO_COM pull-down = 100R. Connected node = divider of
       ~10k pull-up (3.3 V) vs (2*mux_Ron + 100R) -> WELL below the old 1.5 V (a few
       hundred mV, or tens of mV with low-Ron mux); open ~3.3 V. Large margin - set
       thresholds from a bring-up loopback, not a fixed 1.5 V.

 MATRIX CARD REV "2" (2026-07-30) - WHAT CHANGED
================================================================================
Supersedes Matrix_Card-6. Task tracking lives in PROJECT_LOG.md; this section is
the firmware-facing summary.

   MUX SWAP: CD4067B (16:1) -> CD74HC4051 (8:1), 128 parts. HC family is
   characterised at 3.3 V, so the force loop drops from ~2 kohm to a few hundred
   ohm and the excitation ceiling rises from ~0.8 mA to several mA.
   Consequences for firmware:
     - 32 muxes per bank (was 16); enables HI_EN1..32 / LO_EN1..32
     - 3 channel-select bits S0..S2 (was 4); mux=(p-1)>>3, channel=(p-1)&0x07
     - enable bit map is BYTE-SWAPPED: GPB0..7 = EN1..8, GPA0..7 = EN9..16,
       so in the mcp23017 driver's packing: word = (val>>8)|(val<<8)

   TWO BUFFERED I2C SEGMENTS: 9 expanders will not fit in the MCP23017's 8
   addresses, so the bus is split by NTS0102DP level shifters:
     U141 OE = HI_S3 -> BUFF1 : U101 0x20 HI_EN1-16,  U102 0x21 LO_EN1-16,
                                U105 0x22 HI_EN17-32, U106 0x23 LO_EN17-32
     U142 OE = LO_S3 -> BUFF2 : U66  0x24 HI_SENSE_EN1-16,  U67  0x25 ...17-32,
                                U107 0x26 LO_SENSE_EN1-16,  U108 0x27 ...17-32
   The select bit freed by 16:1 -> 8:1 became the segment select. Firmware must
   enable exactly one segment before any expander access.

   RESOLVED IN THIS REV: sense-enable net names (HI_SENSE_EN/LO_SENSE_EN now
   driven); one clock net (SPI1_SCLK everywhere incl. J101); ADC anti-alias front
   end fitted (R234/R235 4.99k 0.1% matched, C33 47nF differential, C142/C143
   4.7nF common-mode, ~320 Hz differential corner); 100k pull-up per mux retained
   on all 128; R131 still 100R 0.01%.

 BENCH SETUP - ADS1232 4-WIRE RIG (2026-07-30)
================================================================================
Stand-in for the ADS124S08 while the Matrix card does not exist yet. Built as a
separate, macro-gated driver so it never ships in the product build.

   Enable with:  -DHT_ENABLE_ADS1232=1     (default 0 = not compiled)
   Files:        Core/Inc/drivers/ads1232.h, Core/Src/drivers/ads1232.c
   Docs:         Doc/ADS1232_bench_wiring.md

   KEY POINT: the ADS1232 is NOT an SPI device. There is no chip select and no
   MOSI. It has one clock in (SCLK) and one data line out (DOUT/DRDY) that
   doubles as the data-ready flag. It is driven bit-banged on two GPIOs; no SPI
   peripheral is used. Gain, data rate and channel are set by STATIC PINS, not
   registers - either strap them with jumpers or drive them from GPIO.

   - ADS1232 has NO internal reference: REFP/REFN must be supplied externally.
   - Confirm measured excitation current with a DMM before trusting any ohms.
